# 2026-04-26 外部状態語彙統一

## 目的

ERIE-on-Lenia の外部世界を、旧来の `resource / hazard / shelter` ではなく、TRM が事前学習し ERIE が行為で関わる `external_state` として統一する。

## 正規語彙

以後のドキュメント、manifest、評価指標では次を正規語彙とする。

- `energy_gradient`
  利用可能な化学的または熱力学的勾配。主に `G_t` を支える。
- `thermal_stress`
  高すぎると構造を傷める環境強度。vent core と habitable band の差を作る。
- `toxicity`
  温度とは独立した腐食性または化学的危険。
- `niche_stability`
  境界維持、制御された交換、観測安定性を助ける局所条件。
- `flow`
  `flow_y / flow_x` で表される輸送場。環境利得やリスクを時間的に運ぶ。

`Lenia` は `z_lenia`、つまり intrinsic CA dynamics を指す。上記の環境場は Lenia parameter ではなく、ERIE-on-Lenia の `external_state` である。

## 互換語彙

既存のコード、CLI、古い artifact との互換性のため、次の alias は残す。

- `resource` -> `energy_gradient`
- `hazard` -> `0.6 * thermal_stress + 0.4 * toxicity`
- `shelter` -> `niche_stability`

旧 CLI 名も当面は残す。

- `--resource-patches`
- `--hazard-patches`
- `--shelter-patches`

新 CLI 名は次を使う。

- `--energy-gradient-patches`
- `--thermal-stress-patches`
- `--niche-stability-patches`

ただし新しい説明文では、旧 CLI は互換 alias として扱い、正規の意味は `energy_gradient / thermal_stress / toxicity / niche_stability` に置く。正規 CLI と旧 CLI の両方が指定された場合、正規 CLI を優先する。

## 評価指標

正規の contact 指標は次とする。

- `contact_energy`
- `contact_thermal`
- `contact_toxicity`
- `contact_niche`
- `mean_contact_energy`
- `mean_contact_thermal`
- `mean_contact_toxicity`
- `mean_contact_niche`

互換指標として次を残す。

- `contact_resource`
- `contact_hazard`
- `contact_shelter`
- `mean_contact_resource`
- `mean_contact_hazard`
- `mean_contact_shelter`

新しい gate や promotion 判断は正規 contact 指標を優先し、旧指標は既存 artifact とテストの互換用に限定する。

## 実装順序

1. ドキュメント内の正規語彙を `energy_gradient / thermal_stress / toxicity / niche_stability / flow` に統一する。
2. `resource / hazard / shelter` は compatibility alias と明記する。
3. runtime history と summary は正規指標を出し、旧指標も alias として残す。
4. runtime / compare / sweep / experiment harness の CLI は正規名を受け取り、旧名も互換 alias として受け取る。
5. `Lenia parameter search` はこの外部状態語彙とは分けて実装する。

## 2026-04-26 実装メモ

- `Lenia parameter search` は `lenia_parameter_search_v1` として、中心域 `mu/sigma` と広域 `mu/sigma`、中心域 sampling ratio、seed ごとの最大試行回数を summary に保存する。
- passive rollout manifest には episode ごとの `parameter_search` を保存する。何回目で採択されたか、中心域/広域のどちらか、リジェクト理由集計を含める。
- `prepare_trm_va_data` の manifest / view manifest / summary には `environment_config_canonical` を保存する。旧 `resource_patches / hazard_patches / shelter_patches` は互換 config として残る。
- agentic cache は `external_state_fields` と `external_state_contact` を保存する。`dataset_harness` は `require_external_state_gate` が有効な contract で、正規 external-state field の存在、contact variability、canonical environment config の存在を gate する。
- action-conditioned intervention data として `intervention_action_onehot`, `intervention_contact_state`, `intervention_next_contact_state`, `intervention_contact_delta`, `intervention_species_contact_delta`, `intervention_viability_delta` を `.npz` に保存する。
- Lenia rollout CLI は `--mu-min`, `--mu-max`, `--sigma-min`, `--sigma-max`, `--center-*`, `--center-sampling-ratio`, `--max-attempts-per-seed` を受け取る。
- `dataset_harness` の passive contract も Lenia parameter search ノブを保持し、`run` 時に `RolloutConfig` へ渡す。
- `dataset_harness` の agentic mode merge summary は、mode 別 summary から `external_state_fields`, `external_state_contact`, `aggregate_intervention_contact_delta_abs_mean` を top-level summary に集約する。
- `dataset_harness plan` は `--energy-gradient-patches`, `--thermal-stress-patches`, `--niche-stability-patches` を受け取り、agentic `EnvironmentConfig` へ渡す。
- agentic mode merge 後も top-level `views/*.jsonl` を再生成し、training plan が role-specific manifest を使える状態を保つ。
